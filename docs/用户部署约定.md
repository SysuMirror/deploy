# 用户部署约定（SSE Deploy / sdpy）

本文说明：如何打 zip / 写 `deploy.sh`（推荐）、以及可选的本机 `compose.yml` 路径。

**数据放哪儿、桶怎么申请、MinIO 凭据与环境变量**：见 [`SSE-Deploy-部署与数据存储指南.md`](./SSE-Deploy-部署与数据存储指南.md)。

## 1. 访问地址规则

平台管理站：`https://ssemarket.cn/sdpy/`

### 默认运行时 `DEPLOY_RUNTIME=sseinfra`（K8s / sseinfra）

测试/正式各对应一个组容器；组内服务听 `8080`，经 frp 映射到宿主机 `23xxx`。  
**用户访问地址与 compose 相同（按模块名拼路径）**，平台部署成功后会：

1. 从组页解析 frp 端口（如 `23002`）
2. 写入平台网关 `data/nginx/modules.conf`（`/sdpy/...` → `GATEWAY_UPSTREAM_HOST:23002`）
3. 执行 `GATEWAY_RELOAD_CMD` 重载网关 nginx
4. 写回访问链接（正式例：`https://ssemarket.cn/sdpy/{模块名}/`）

| 环境 | 前端 / 单端口服务 | API 路径（同上游） |
|------|-------------------|-------------------|
| 测试 | `https://ssemarket.cn/sdpy/test/{模块名}/` | `.../sdpy/test/{模块名}-api/` |
| 正式 | `https://ssemarket.cn/sdpy/{模块名}/` | `.../sdpy/{模块名}-api/` |

`:23xxx` 仅作网关上游，不要当对外入口发给用户。

> **后续计划**：按 Header/Query 灰度分流（`module_domains.gray_*` 已预留）；子域名与自定义域名 **已支持**，见 [`plans/2026-08-21-子域名访问模式.md`](./plans/2026-08-21-子域名访问模式.md) 与模块页「访问域名」。

### 可选运行时 `DEPLOY_RUNTIME=compose`（本机 docker）

| 环境 | 前端 | 后端 API |
|------|------|----------|
| 测试 | `https://ssemarket.cn/sdpy/test/{模块名}/` | `https://ssemarket.cn/sdpy/test/{模块名}-api/` |
| 正式 | `https://ssemarket.cn/sdpy/{模块名}/` | `https://ssemarket.cn/sdpy/{模块名}-api/` |

模块名：小写字母开头，仅 `a-z0-9-`，全局唯一。不可使用保留字：`test`、`api`、`oauth`、`login`、`projects`、`modules`、`assets` 等；不可以 `-api` 结尾。

## 2. 压缩包结构（推荐：K8s）

上传的 `.zip` 解压后**至少**包含可执行：

```text
deploy.sh                 # 必须；监听 0.0.0.0:$PORT（通常 8080）；换行须为 LF（勿 CRLF）
# 其余业务代码按你的脚本约定摆放
```

平台流程：建组 → Pod Running → 经跳板 `kubectl cp` 同步包 → supervisord 执行 `deploy.sh`。  
Windows 打的 zip 若带 CRLF，会出现 `set: pipefail: invalid option name`；平台会在解压后尽量 `sed` 去掉 `\r`，打包时仍请用 LF。

### 2.0 必须听 `0.0.0.0:8080`（否则 Web / frp 全不通）

sseinfra 组页会提示：

> 容器内应用需绑定 **0.0.0.0:8080** 才能通过 Web 地址访问。

| 项 | 要求 |
|----|------|
| 地址 | **`0.0.0.0`**（不要只绑 `127.0.0.1` / `localhost`） |
| 端口 | 环境变量 **`PORT`**（平台注入，默认 **`8080`**） |
| 进程 | `deploy.sh` **前台常驻**（`exec …`），勿后台化后退出 |

只绑回环时：组内 `curl 127.0.0.1:8080` 可能正常，但公网 `:23xxx` 与平台网关反代都会失败。  
Go/Gin 请用 `0.0.0.0:$PORT` 或等价的 `:$PORT`（勿写成 `127.0.0.1:$PORT`）。

组容器内**没有 Docker**，无法直接 `docker compose up`。仅含 `frontend/` + `backend/` + `compose.yml`、没有 `deploy.sh` 的旧包，在 sseinfra 运行时会部署失败；请下载「Git 模板」补上 `deploy.sh`，或临时把 API 设为 `DEPLOY_RUNTIME=compose`。

允许 zip 外再包一层目录（平台会自动识别）。

模板：模块页「下载 Git 模板」或仓库 [`deploy/examples/templates/sseinfra-module/`](../deploy/examples/templates/sseinfra-module/)。

## 2.1 Git 分支部署

模块配置 Git 仓库后，选分支部署。仓根同样须有可执行 `deploy.sh`。平台经 sseinfra 表单：建组 → clone → supervisord。

支持平台：

| 平台 | 地址示例 | 私有仓库令牌 |
|------|----------|--------------|
| Gitee | `https://gitee.com/owner/repo` | 可用平台统一 token；也可模块级填写 |
| GitHub | `https://github.com/owner/repo` | GitHub PAT |
| 其他 | 任意 `https://` 仓库 | 用户名 + 令牌 |

使用要点：

1. 模块详情页配置仓库地址、默认分支、可选令牌。
2. 弹窗切到「Git 分支」填写分支后部署。
3. **令牌仅存服务端，接口不回传明文**；日志中 clone 地址会打码。
4. 「一键晋升正式」对 Git = 再拉同一分支最新提交。

## 2.2 本机 compose（仅 `DEPLOY_RUNTIME=compose`）

```text
frontend/                 # 含 Dockerfile
backend/                  # 含 Dockerfile
compose.yml               # 或 docker-compose.yml / .yaml
```

示例：[`deploy/examples/sample-app/`](../deploy/examples/sample-app/)。

## 2.3 迁移旧本机服务与数据 → K8s

若某环境仍占用本机端口（旧 docker compose），模块页会提示遗留并提供 **「迁移到 K8s」**：

1. 打包同步 `{MODULE_DATA_ROOT}/{模块}/{test|prod}` → 组容器 `/home/cloud/data`（尽量兼容 `/data`）
2. 用 Git 或带 `deploy.sh` 的压缩包在 sseinfra 重新部署
3. 成功后 `docker compose down` 旧项目并刷新 nginx
4. **宿主机 MODULE_DATA 目录不删除**，可作备份

API：`GET /api/v1/deployments/modules/:id/legacy`、`POST .../migrate`（body: `env`，可选 `source`/`force`/`confirmAgentGenerate`）。压缩包缺 `deploy.sh` 时返回 **409 NEED_AGENT_DEPLOY_SH**，前端确认后再带 `confirmAgentGenerate=true` 入队；Agent 在 worker 内生成，日志页可随时取消。部署同理。

应用侧请改读 `SDPY_DATA_DIR` 或 `/data`（迁移后指向组内持久化目录）。

## 2.3.1 对象存储（MinIO / 像「文件夹」的 key）

大文件、图床原图等宜放 [sseinfra 存储](http://ssemarket.cn:24000/storage)，勿塞满组 PVC。

- **不是** FUSE 挂载目录；用 S3 API，对象名可用 `images/…` 路径风格。
- 模块页入口 **「对象存储」→「进入管理」**（路由 `/modules/:id/object-storage`）按步骤操作。
- **「申请对象存储」** → 管理员审批 → 自动建桶并签发密钥（**标签必须等于组名**）→ **重新部署**后注入 `MINIO_*`。
- **「确保桶存在」**：幂等建桶+发密钥（不删已有桶）。
- **「同步历史数据到桶」**：把宿主机 `MODULE_DATA` 上传到对应桶；组须 Running。
- **生命周期**：桶随模块保留；**释放 K8s 组 / 删除模块默认不删桶**。管理台「系统」页可查看绑定。
- 应用读 `MINIO_ENDPOINT` / `MINIO_ACCESS_KEY` / `MINIO_SECRET` / `MINIO_BUCKET`。

## 2.4 测试 / 正式隔离（平台基础）

| 维度 | 测试 (`test`) | 正式 (`prod`) |
|------|---------------|---------------|
| 业务数据 | `{MODULE_DATA_ROOT}/{模块}/test/` | `{MODULE_DATA_ROOT}/{模块}/prod/` |
| 环境变量 | 模块页「环境变量」独立配置 | 独立配置（**晋升不复制**） |
| K8s 组 | 独立组容器 | 独立组容器 |

模块页当前环境下点 **「环境变量」**：支持 JSON 或 `.env` 文本编辑。保存后按槽位入库；**部署该环境时**写入应用根目录 `.env`（可读），并注入 supervisord / sseinfra 组环境。平台键（`PORT`、`SDPY_*`、`DATA_DIR` 等）部署时覆盖用户同名项。

模块页 **「下载数据」**：把当前环境 `{MODULE_DATA_ROOT}/{模块}/{env}` 打成 zip（包内顶层目录 `{模块}-{env}/`）。预检：`GET .../data-export`；下载：`GET .../data-export.zip?env=`。默认粗估上限约 512MB（`MODULE_DATA_EXPORT_MAX_MB`）。说明：导出的是**宿主机 MODULE_DATA**；若数据仅在 K8s Pod 内且宿主机已空，需另从组内备份。

API：`GET/PUT /api/v1/modules/:id/env-config`（query/body 带 `env=test|prod`）。

没有 `deploy.sh` 时：模块页可用 **「部署 Agent」**（须管理员配置 AI/vLLM，且模型支持 **function calling / tools**）。Agent 可自行探索包结构并写入配置与部署脚本；**不能改业务源码**（详见下文边界）。也可下载 Git 模板手改。

### Agent 工具与边界

| 工具 | 作用 |
|------|------|
| `list_dir` | 列目录 |
| `read_file` | 读任意文本（含源码，只读） |
| `get_write_boundary` | 查询可写规则 |
| `write_file` | 写入白名单路径 |
| `done` | 结束任务 |

**可写**：`deploy.sh` / `start.sh` 等部署脚本、`compose.yml`、`Dockerfile`、`.dockerignore`、`nginx.conf`、`supervisord.conf`、`Procfile`、`.env.example`、根或 frontend/backend 的 `package.json` / `requirements.txt` 等配置。  
**禁止写**：`.ts` / `.js` / `.vue` / `.py` 等业务源码、真实 `.env`（密钥）。平台对 `write_file` 做强制校验，越权会拒绝。

完整流水线流程图：[`plans/2026-08-21-K8s部署流水线.md`](./plans/2026-08-21-K8s部署流水线.md)。

## 3. compose.yml 要求（仅本机 compose 运行时）

必须定义两个服务名：**`web`**（前端）与 **`api`**（后端）。

端口由平台注入的环境变量控制（须映射到宿主机，供公共 nginx 反代）：

- `WEB_HOST_PORT` — 前端宿主机端口  
- `API_HOST_PORT` — 后端宿主机端口  

> 公共 nginx 跑在 Docker 内时，**不要**写成 `127.0.0.1:${PORT}:…`（容器经 `host.docker.internal` 访问不到仅绑回环的端口，会 502）。请用 `"${WEB_HOST_PORT}:80"` / `"${API_HOST_PORT}:3000"`。

示例：

```yaml
services:
  web:
    build:
      context: ./frontend
      args:
        # 构建期写入前端的 API 公网地址（见第 4 节）
        VITE_API_BASE: ${SDPY_API_PUBLIC_URL}
    ports:
      - "${WEB_HOST_PORT}:80"
    environment:
      SDPY_ENV: ${SDPY_ENV}
      SDPY_MODULE: ${SDPY_MODULE}

  api:
    build:
      context: ./backend
    ports:
      - "${API_HOST_PORT}:3000"
    environment:
      SDPY_ENV: ${SDPY_ENV}
      SDPY_MODULE: ${SDPY_MODULE}
      PORT: "3000"
      # 若后端需要知道自身公网前缀
      PUBLIC_BASE: ${SDPY_API_PUBLIC_BASE}
```

平台每次部署会在工作目录生成 `.env.sdpy`，并执行：

```bash
docker compose -p sdpy-{env}-{模块名} --env-file .env.sdpy up -d --build --force-recreate
```

可选勾选 `--no-cache`。compose 项目名固定为 `sdpy-test-{name}` / `sdpy-prod-{name}`，与服务器上其他容器隔离。

### 平台注入的变量

| 变量 | 含义 |
|------|------|
| `SDPY_ENV` | `test` 或 `prod` |
| `SDPY_MODULE` | 模块名 |
| `WEB_HOST_PORT` / `API_HOST_PORT` | 本机映射端口 |
| `SDPY_PUBLIC_BASE` | 前端路径前缀，如 `/sdpy/test/my-app` |
| `SDPY_API_PUBLIC_BASE` | 后端路径前缀，如 `/sdpy/test/my-app-api` |
| `SDPY_PUBLIC_URL` | 前端完整 URL |
| `SDPY_API_PUBLIC_URL` | 后端完整 URL（**前端应配置为此值**） |
| `SDPY_DATA_DIR` | 宿主机模块数据目录 `{MODULE_DATA_ROOT}/{模块名}/{test\|prod}`，默认 `/root/SSE_Market/sse-sdpy/data/{模块名}/prod`；平台会自动创建并 bind 到 `api` 容器的 `/data` |

后端若有 SQLite / 上传文件，请写到容器内 **`/data`**（不要写镜像层）。平台每次部署会：

1. 若 `/root/SSE_Market/sse-sdpy/data/{模块名}/{test|prod}` 不存在则创建  
2. 挂载到该模块 `api` 服务的 `/data`  
3. 重建容器时数据仍在宿主机，不会丢  

测试与正式数据完全隔离，互不影响。

## 4. 前端如何配置上云后的后端域名

浏览器里的 JS 只能访问公网路径，不能写 `http://localhost:3001`。

### 推荐（与 iWiki 一致）

1. 前端使用环境变量，例如 Vite：`VITE_API_BASE` / `import.meta.env.VITE_API_BASE`
2. 在 **Dockerfile 构建参数** 中传入平台提供的 `SDPY_API_PUBLIC_URL`
3. 请求时拼：`${VITE_API_BASE}/your/path`

前端 Dockerfile 示例：

```dockerfile
ARG VITE_API_BASE=
ENV VITE_API_BASE=$VITE_API_BASE
RUN npm ci && npm run build
```

模块详情页会展示「应填写的后端 API」并支持复制。测试与正式环境的 URL 不同，**请分别构建/部署**（平台对 test / prod 各跑一套 compose）。

### 后端注意

- 读 `SDPY_ENV` 区分测试/正式  
- 若有 CORS，放行 `https://ssemarket.cn`  
- 若应用挂在子路径，注意 cookie / redirect 是否需要 `PUBLIC_BASE`

## 5. 流量如何到达你的容器（隔离说明）

公共 `nginx_proxy` **不手写**逐模块 location，一次性 `include` 平台生成的：

`${SDPY_HOST_DATA}/data/nginx/modules.conf`

部署成功后该文件含例如：

```nginx
location /image/ {
  proxy_pass http://host.docker.internal:23002/;  # 端口来自 sseinfra 组 Web
}
```

| 路径 | 去向 |
|------|------|
| `/sdpy-api/` | 部署平台 API |
| `/sdpy/` | 部署平台管理站 SPA |
| `/image/`、`/sdpy/{模块}/` 等 | **modules.conf** → K8s frp 端口或本机 compose 端口 |

**务必保证**公共 nginx 的 `include` 路径与部署日志里「已更新平台网关模块路由: …」为**同一文件**。  
若仍 include 旧的 `/opt/release-sdpy/...`，而 API 写到 `/root/SSE_Market/sse-sdpy/...`，则 `/image` 不会反代，请求会落到站点根（博客）。

改 include 后执行：`docker exec <nginx容器> nginx -s reload`（或你的 `GATEWAY_RELOAD_CMD`）。
