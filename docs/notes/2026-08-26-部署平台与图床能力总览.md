# 部署平台与图床能力总览（开发新应用前探查）

> 日期：2026-08-26  
> 目的：后续在本基建上开发新应用前，对齐登录、部署、数据存储约定。

## 结论速览

| 系统 | 入口 | 登录 | 部署 | 业务数据 |
|------|------|------|------|----------|
| **SSE Deploy（sdpy）** | https://ssemarket.cn/sdpy/ | SSE Market OAuth（`ssemarket-sdpy`） | 默认 K8s/sseinfra：`deploy.sh` + zip/Git；可选本机 compose | 平台库在 `DEPLOY_DATA_DIR`；用户模块见下表 |
| **图床 imagebed** | 管理页 `…/image/`；API `…/image-api/` | 同上 OAuth + Web JWT；脚本用个人 Token `imgb_…` | 已作为模块 `image` 挂在 sdpy | SQLite/JWT → PVC `DATA_DIR`；图片 → MinIO（有 `MINIO_*`）或本地盘 |

## 1. SSE Deploy（部署平台）

### 登录

- 身份：软工集市 **OAuth 2.0 授权码**（与 iWiki / 图床同一 IdP）。
- 管理站：未登录跳转集市授权 → 回调 → 本地会话。
- 角色：平台管理员（`PLATFORM_ADMIN_OAUTH_IDS`）、项目 Owner / Developer / Viewer。
- 运维侧另有 **sseinfra 面板**（`:24000`）账号，供建组/建桶/传包，与用户 OAuth 分离；管理台「管理员 → sseinfra 面板登录」配置。

### 部署方式（当前默认 `DEPLOY_RUNTIME=sseinfra`）

1. 登录 sdpy → 项目 → 注册模块名（`a-z0-9-`，全局唯一）。
2. 上传含可执行 **`deploy.sh`** 的 zip，或配置 Git 分支部署。
3. 选 **测试 / 正式** → 部署：建组 → Pod Running → 传包 → supervisord 跑 `deploy.sh`。
4. 应用必须监听 **`0.0.0.0:$PORT`**（通常 `8080`），脚本前台常驻。
5. 网关把路径反代到组 frp 端口；**勿把 `:23xxx` 当对外入口**。

访问 URL 约定：

| 环境 | 前端 | API（若独立） |
|------|------|----------------|
| 测试 | `/sdpy/test/{模块}/` | `/sdpy/test/{模块}-api/` |
| 正式 | `/sdpy/{模块}/` | `/sdpy/{模块}-api/` |

模板：`deploy/examples/templates/sseinfra-module/`；模块页也可「下载 Git 模板」。

可选：`DEPLOY_RUNTIME=compose` 时用 `frontend/` + `backend/` + `compose.yml`（服务名 `web`/`api`）。

### 数据存储（用户模块）

同一模块 test/prod **完全隔离**：

| 层级 | 路径/命名 | 存什么 | 删组是否丢 |
|------|-----------|--------|------------|
| 宿主机 MODULE_DATA | `{MODULE_DATA_ROOT}/{模块}/{test\|prod}/` | 备份/迁移/同步源 | 默认不删 |
| K8s 组 PVC | Pod 内 `/home/cloud/data`（兼容 `/data`） | SQLite、JWT、本地文件 | **删组会丢** |
| MinIO 桶 | 桶名 = 组名，如 `sdpy-{模块}-t/p` | 大文件 / 图床原图等 | **默认不删** |

平台注入常用变量：`PORT`、`SDPY_DATA_DIR`/`DATA_DIR`、`SDPY_ENV`、`SDPY_MODULE`、`SDPY_PUBLIC_*`；配齐对象存储后还有 `MINIO_ENDPOINT` / `ACCESS_KEY` / `SECRET` / `BUCKET`（仅集群内可达 endpoint）。

对象存储：模块页「对象存储」申请/确保桶 → 管理员审批或幂等建桶 → 密钥 label **必须等于组名** → 部署后注入 → 可选「同步历史数据到桶」。

正式文档：`docs/SSE-Deploy-部署与数据存储指南.md`、`docs/用户部署约定.md`。

## 2. 图床（imagebed）

### 登录与鉴权

| 通道 | 方式 | 用途 |
|------|------|------|
| Web | SSE Market OAuth → 本地 JWT | 管理页上传/列表/Token 管理 |
| API | 个人 Token `imgb_<64hex>`（Bearer 或 `?token=`） | 脚本 / Typora / Agent 上传 |

- 生产管理页：`https://ssemarket.cn/image/`（或子域名，以现网为准）
- API：`https://ssemarket.cn/image-api/`（`POST /api/upload`）
- Agent 配置：`~/.imagebed/config.json`（`base_url` / `api_base_url` / `token`）
- OAuth 环境变量统一 **`IMAGEBED_OAUTH_*`** 前缀，避免与 sdpy 自身 `OAUTH_*` 冲突。

### 部署

- 仓库：`基础服务/imagebed/`
- 推荐：`deploy/pack-sseinfra.ps1` → zip（含 `deploy.sh`）→ 模块名 **`image`** 上传到 sdpy
- 备选：`pack.ps1` → compose 双容器（仅 compose 运行时）

### 数据

- **元数据**：SQLite（`imagebed.db`）+ JWT 密钥 → `DATA_DIR` / PVC
- **二进制**：`MINIO_*` 四元组齐全 → MinIO（日志 `backend: minio:桶名`）；否则本地 `DATA_DIR` 下 `images/` / `thumbs/`
- 用户隔离：列表/删改按 `user_id`；公开图直链 `/i/...`，私有图需本人 JWT/Token

API 细节：`基础服务/imagebed/docs/api-upload.md`、skill `imagebed-upload`。

## 3. 开发新应用时建议清单

1. **登录**：在集市注册独立 OAuth 应用；回调指向前端 `/oauth/callback`；生产 `redirect_uri` 含路径前缀。
2. **部署包**：仓根 `deploy.sh`（LF），听 `0.0.0.0:$PORT`；可先下载 sseinfra 模板。
3. **持久化**：小库/会话 → `DATA_DIR`；大文件 → 申请 MinIO 桶，读平台注入的 `MINIO_*`。
4. **前端 API 地址**：构建期用 `SDPY_API_PUBLIC_URL` / `VITE_API_BASE`，勿写死 localhost。
5. **图床复用**：业务若只需发图，直接调现网 `image-api` + Token，不必自建存储。
6. **测试/正式**：环境变量分槽；晋升不自动复制 env；验收用模块页「访问链接」。

## 未决 / 待用户确认

- 新应用的模块名、是否独立 OAuth app、是否需要对象存储桶。
- 正式入口用路径 `/sdpy/{模块}/` 还是子域名（平台已支持模块多域名）。
