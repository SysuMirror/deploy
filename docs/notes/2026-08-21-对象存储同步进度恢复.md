# 对象存储同步：后台任务与页面重进恢复

## 背景

同步本身是 API 进程内异步任务（`minio-sync-jobs` 内存 Map），但前端退出页面后停轮询且不查询最新任务，重进后进度 UI 空白，看起来像「不是后台」。

## 结论

- 任务一直在服务端跑；丢的是前端展示。
- 新增 `GET /modules/:id/object-storage/sync?env=` 返回该模块+环境最新任务。
- 进页 / 切环境时自动 `resumeSyncIfAny` 续轮询；同环境已有 running 时再点同步会复用任务。
- 限制：`sdpy-api` 容器重启会清空内存任务列表（进行中的上传可能被中断），与本次 UI 恢复无关。

## 改动

- `minio-sync-jobs.ts`：`findLatestMinioSyncJob`；running 复用
- `routes/modules.ts`：GET sync 列表/最新
- `ModuleObjectStorageView.vue` + `api.ts`：重进恢复

# 2026-08-22 追加：Pod 内 minio 库安装失败

## 现象

同步最后一步 `pip install minio` 报 `externally-managed-environment`（Debian PEP668）；加 `--break-system-packages` 后 `--user` 安装到 `~/.local` 仍 `ModuleNotFoundError`。

## 结论与修复

- `ensure_minio` 改为**系统级安装优先**（root 下 `pip install --break-system-packages minio`，落 `/usr/local` 必进 sys.path），`--user` 仅兜底。
- 失败时把 pip 完整 stderr/stdout 带回日志（`run` + `capture_output`，截 800 字符），便于继续排查。
- 写组 env `setEnvMany` 已在上一轮移到上传之后，本次日志确认推数据与上传为同一 Pod，重建丢数据问题已解决。

## 验证

- 仅 API 包 `dist-packages/sdpy-api-only-*.zip` 部署后重试同步。
