# 旧 compose 服务与 MODULE_DATA 迁移到 K8s

日期：2026-08-21

## 背景

默认运行时改为 sseinfra 后，历史上本机 docker compose 的模块（宿主端口 + `MODULE_DATA_ROOT` bind `/data`）需要迁到组容器，并带走业务数据。

## 结论

模块详情在识别到「遗留 compose 槽位」时提供 **迁移到 K8s**：

1. 同步 `{MODULE_DATA_ROOT}/{module}/{env}` → Pod `/home/cloud/data`（并尽量兼容 `/data`）
2. 按 Git / 带 `deploy.sh` 的包走现有 sseinfra 部署
3. 成功后停本机 compose、刷新 nginx；宿主机数据目录保留备份

## 关键

- `legacy-migrate.ts`：遗留检测、停旧站
- `sseinfra-pod.ts`：`syncHostDataToPod`
- `POST /v1/deployments/modules/:id/migrate`、`GET .../legacy`
- Worker：`action=migrate` 时同步数据并注入 `SDPY_DATA_DIR`

## 未决

- 超大目录（>约 1.5GB）需人工传包
- ~~旧仅 compose、无 deploy.sh 的制品~~：迁移时若已配 LLM，会自动 Agent 生成 deploy.sh；未配 LLM 仍须手补或 Git

## 更新（同日）

迁移 `POST .../migrate`：包路径缺 `deploy.sh` → `ensurePackageHasDeploySh`（部署 Agent）→ 再入队。
