# 对象存储页：审批门禁 + 桶内容浏览

## 背景

用户反馈：

1. 需要按环境看到 MinIO 桶里实际存了什么；
2. 「确保桶存在」对普通成员可直接建桶/发密钥，**绕过** `minio_bucket` 审批，需改掉；
3. 页面需按上述约束重做交互。

## 结论

### 审批

- `POST /v1/modules/:id/object-storage/ensure`：**仅平台管理员**可调用；非管理员返回 403，引导走申请审批。
- 前端：成员只保留「申请对象存储」；管理员在页底独立「运维工具」区提供「确保桶存在」（与申请流程分离，二次确认）。
- `POST .../object-storage/sync` 与 `syncHistoryDataToBucket`：绑定为 `none` / `orphaned` 或缺绑定则拒绝，须先审批开通。

### 桶内容

- 新增 `GET /v1/modules/:id/object-storage/credentials`：从 sseinfra `/storage` 面板解析 Access Key + Secret（`data-secret`）
- 列出桶对象优先读面板密钥，不再仅依赖 GPU `minio_keys.json`（修复「已开通但读不到密钥」）
- 前端开通后展示「连接凭证」区（可复制、Secret 可显示/隐藏）

### UI

页面结构：环境 Tab → 当前绑定 → 开通与同步（蓝钮引导申请）→ **桶内容浏览器** → 同步进度 / 日志 → 双环境一览。

## 关键路径

- `apps/deploy-api/src/routes/modules.ts`（ensure 权限、objects、sync 门禁）
- `apps/deploy-api/src/services/minio-sync.ts`（`listModuleBucketObjects`、同步前校验）
- `apps/deploy-web/src/views/ModuleObjectStorageView.vue`
- `apps/deploy-web/src/services/api.ts`（`listModuleBucketObjects`）
