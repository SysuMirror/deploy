## 1. `ssemarket.cn:24000` 是什么

- **不是** 通用 K8s REST 控制面，也不是已实现的 `docs/k8s-runtime-api.md`。
- **是** GPU 机 WZ8 上的 **student-platform（面板品牌 sseinfra）**：给人开「开发机」容器。
- 入口：Flask Web（Cookie + CSRF），经集市机 **frps** 转到 WZ8 `:8090`。

| 公网 | 含义 |
|------|------|
| `:24000` | 管理面板 |
| `:22001+` | 学生组 SSH |
| `:23001+` | 学生组 Web（容器内 8080） |
| `:2222` | GPU 宿主机 SSH（密钥/跳板，面板密码登不上） |

真实机器：Tailscale `sse-gpu-3x4090d`，主机名 `WZ8`，3×4090D。  
代码：`/opt/student-platform`；systemd：`student-platform-web.service`。  
编排：本机 k3s，ns `students`，镜像 `docker.io/sse/student-ubuntu:24.04`。

从集市机跳板：`ssh root@ssemarket.cn` → `sudo -u sse -H ssh gpu`。

## 2. 现有「申请/删除容器」接口

有，但是 **HTML 表单**，不是 JSON API：

- 创建：`POST /add`
- 删除：`POST /group/<name>/delete`
- 启停重启 / 改资源 / 重置密码：同前缀表单

可手工或脚本带 Cookie+CSRF 调用，**不适合**直接作为 SDPY 正式流水线契约。语义却对：流水线里「每个服务单独申请一台机子」。

## 4. 已拍板方向（本会话）

- **先不落地对接代码**，重新设计。
- **砍掉用户压缩包上传**，改为 **Gitee 仓库**。

- 后续流水线：服务 → 申请容器（机子）→（再谈怎么在机子上跑构建/部署）。

## 5. iWiki 可复用模式（摘要）

- Env：`CODE_WIKI_GITEE_USERNAME` + `CODE_WIKI_GITEE_TOKEN`（优先，锁定后台）
- 或管理后台写入 `platform_settings`
- 用户：`POST` 只带 `repoUrl`
- 平台：`fetchRepoArchive` 浅克隆，失败后用平台凭证 Basic Auth 重试
- **无** Gitee OAuth、无 webhook（SDPY 若要自动部署需另议 webhook / 轮询）

关键路径：`iwiki/apps/iwiki-api/src/services/code-wiki-git-credentials.ts`、`code-wiki-fetch.ts`；后台 UI：`AdminSettingsView.vue`。
