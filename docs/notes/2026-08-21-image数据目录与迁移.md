# image 迁移未带上旧图：目录名不一致

日期：2026-08-21

## 结论

平台「迁移到 K8s」只同步 `{MODULE_DATA_ROOT}/{模块名}/{env}`。  
旧 compose 图床 bind 的是 **`…/data/imagebed/`**（无 test/prod），模块名 `image` 时平台读的是 **`…/data/image/prod/`**。  
未先 rsync 对齐时，迁移日志常见「数据包几乎为空，跳过 scp」→ 组内仍是空库 → 页面「共 0 张」。

## 补救

```bash
mkdir -p /root/SSE_Market/sse-sdpy/data/image/prod
rsync -a /root/SSE_Market/sse-sdpy/data/imagebed/ /root/SSE_Market/sse-sdpy/data/image/prod/
# 再在 SDPY 点一次「迁移到 K8s」，看日志应有「同步数据 X.XXMB」
```

组内确认：`ls -la /home/cloud/data/` 应有 `imagebed.db` 与图片目录。

## 重部署会不会丢数据

| 操作 | 组内 `/home/cloud/data` |
|------|-------------------------|
| 普通重新部署（复用组） | **保留**（只换程序） |
| `SSEINFRA_FORCE_RECREATE=1` / 删组 / 删模块 | **随 PVC 清空** |
| 普通部署（非 migrate） | **不会**从宿主机再同步一遍 |

宿主机 `MODULE_DATA` 迁移成功后默认不删，可作备份。业务数据不要只依赖组盘。
