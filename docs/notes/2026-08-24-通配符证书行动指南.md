# 行动指南：让 `*.ssemarket.cn` 使用现有证书路径

> 日期：2026-08-24  
> 目标：签发（或确认）含 `ssemarket.cn` + `*.ssemarket.cn` 的证书，仍落在现有目录，nginx 各子域共用同一对 pem。  
> 入口机证书目录：宿主机 `/root/SSE_Market/Nginx/` ↔ 容器 `/etc/letsencrypt/`

---

## 总览（你将做完这些）

| 步骤 | 做什么 | 预计耗时 |
|------|--------|----------|
| 0 | SSH 上入口机，确认路径与 nginx 容器名 | 2 min |
| 1 | 看当前证书 SAN 是否已有通配符 | 2 min |
| 2 | DNS：加 `*.ssemarket.cn` 泛解析（若还没有） | 5–30 min（含生效） |
| 3 | 用 DNS-01 扩签/重签到 `*.ssemarket.cn` | 10–20 min |
| 4 | 确认文件仍在 `live/ssemarket.cn/` | 1 min |
| 5 | 核对 nginx 全部 `ssl_certificate` 指向同一路径 | 5 min |
| 6 | `nginx -t` + reload | 2 min |
| 7 | 浏览器 / openssl 验收 | 5 min |
| 8 |（重要）安排通配符自动续期 | 视 DNS 厂商 |

## 步骤 0：登录并确认环境

在能 SSH 的机器上：

```bash
ssh root@ssemarket.cn
```

确认证书与续期脚本存在：

```bash
ls -la /root/SSE_Market/Nginx/live/ssemarket.cn/
# 应能看到 fullchain.pem  privkey.pem  chain.pem  cert.pem

ls -la /root/SSE_Market/certbot-renew.sh 2>/dev/null || echo "无 renew 脚本，后面步骤 8 再补"

docker ps --format '{{.Names}}' | grep -i nginx
# 记下容器名，下文用 NGINX 代替；现网常见：
#   sse_market_server-nginx_proxy-1
```

设一个变量，后面少打字（按实际改名）：

```bash
export NGINX=sse_market_server-nginx_proxy-1
export CERT_DIR=/root/SSE_Market/Nginx
export LIVE=$CERT_DIR/live/ssemarket.cn
```

确认容器挂载正确：

```bash
docker inspect "$NGINX" --format '{{range .Mounts}}{{.Source}} -> {{.Destination}}{{"\n"}}{{end}}' \
  | grep -E 'letsencrypt|Nginx|certbot'
```

期望类似：

```text
/root/SSE_Market/Nginx -> /etc/letsencrypt
/root/SSE_Market/certbot/www -> /var/www/certbot
```

## 步骤 1：看当前证书覆盖了哪些名字

```bash
openssl x509 -in "$LIVE/fullchain.pem" -noout -dates
openssl x509 -in "$LIVE/fullchain.pem" -noout -text | grep -A2 'Subject Alternative Name'
```

### 怎么判断

| 输出里有 | 含义 | 下一步 |
|----------|------|--------|
| `DNS:*.ssemarket.cn` 且有 `DNS:ssemarket.cn` | 证书已够用 | **跳到步骤 2**（只确认 DNS）→ 再步骤 5–7 |
| 只有 `ssemarket.cn`、`www…`、`cloud…` 等具体名 | 还不是通配符 | 必须做 **步骤 3** |
| 文件不存在 / 报错 | 路径不对 | 停下来核对挂载与 `live/` 目录名 |

同时记下到期日（`notAfter`），续期策略见步骤 8。

## 步骤 2：DNS 泛解析（证书有了也要解析到入口机）

在 **ssemarket.cn 的域名解析控制台**（阿里云 / DNSPod / Cloudflare 等）：

1. 查出主站当前 IP：

```bash
# 在任意能上网的机器
dig +short ssemarket.cn A
# 或
nslookup ssemarket.cn
```

2. 添加（或确认已有）记录：

| 主机记录 | 类型 | 记录值 | TTL |
|----------|------|--------|-----|
| `*` | A | 与 `ssemarket.cn` **同一个** 公网 IP | 600 或默认 |
| `@`（或根） | A | 同上（本来就有） | — |

说明：

- `*` 表示 `任意一级子域`，如 `cloud.ssemarket.cn`、`foo.ssemarket.cn`
- **不含** 更深层级（如 `a.b.ssemarket.cn` 需要 `*.b.ssemarket.cn` 另配，一般用不到）
- 若已有单独的 `cloud` A 记录，可保留；与 `*` 不冲突时，具体记录优先

3. 等待生效后验证：

```bash
dig +short cloud.ssemarket.cn A
dig +short random-test-xyz.ssemarket.cn A
# 两者都应解析到与 ssemarket.cn 相同的 IP
```

未生效前不要急着验收 HTTPS。

## 步骤 3：签发 / 扩签通配符（DNS-01）

### 3.1 为什么不能用以前的 HTTP 方式

- 以前给 `cloud.ssemarket.cn` 用的 `--webroot` / HTTP-01 **不能**签 `*.ssemarket.cn`
- 通配符 **必须** DNS-01：在域名下加一条 TXT 记录做验证

### 3.2 备份现有证书（必做）

```bash
ts=$(date +%Y%m%d-%H%M%S)
mkdir -p /root/SSE_Market/Nginx-backup
cp -a "$CERT_DIR/live/ssemarket.cn" "/root/SSE_Market/Nginx-backup/live-ssemarket.cn.$ts"
cp -a "$CERT_DIR/archive/ssemarket.cn" "/root/SSE_Market/Nginx-backup/archive-ssemarket.cn.$ts" 2>/dev/null || true
echo "备份完成: $ts"
```

### 3.3 确认本机有 certbot

```bash
which certbot || apt-get update && apt-get install -y certbot
certbot --version
```

若习惯用 docker 跑 certbot，也可，但要把 `$CERT_DIR` 挂进容器，且 `cert-name` 仍用 `ssemarket.cn`。下文以宿主机 certbot 为例。

### 3.4 手动 DNS 验证签发（通用，不依赖 DNS 插件）

在 **tmux/screen** 里跑（验证期间终端不能断）：

```bash
certbot certonly \
  --manual \
  --preferred-challenges dns \
  --cert-name ssemarket.cn \
  -d ssemarket.cn \
  -d '*.ssemarket.cn' \
  --config-dir "$CERT_DIR" \
  --work-dir "$CERT_DIR/work" \
  --logs-dir "$CERT_DIR/logs" \
  --agree-tos \
  --email 你的邮箱@example.com \
  --no-eff-email
```

说明：

- `--cert-name ssemarket.cn`：**必须**，这样会更新/覆盖现有 `live/ssemarket.cn/`，nginx **不用改路径**
- `-d ssemarket.cn` + `-d '*.ssemarket.cn'`：根域 + 通配（通配 alone **不含** 根域）
- `--email`：改成你们运维邮箱（到期提醒）

### 3.5 按提示加 TXT（关键）

certbot 会停住并打印类似：

```text
Please deploy a DNS TXT record under the name:
_acme-challenge.ssemarket.cn
with the following value:
xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

到 DNS 控制台：

| 主机记录 | 类型 | 记录值 |
|----------|------|--------|
| `_acme-challenge` | TXT | （粘贴 certbot 给的那一串，不要加引号） |

保存后，**另开一个 SSH 窗口** 查是否生效：

```bash
dig +short TXT _acme-challenge.ssemarket.cn
# 应能看到刚加的那串；若空，等 1–5 分钟再 dig
```

有时 Let's Encrypt 要验证两个名字，会要求 **两条** TXT（或先后两次）。都加齐、`dig` 能查到后，回到 certbot 窗口按 **Enter** 继续。

成功标志：出现 `Congratulations` / `Certificate is saved at: .../live/ssemarket.cn/fullchain.pem`。

### 3.6 若 certbot 提示「会替换现有证书」

选 **同意替换 / Update**（目标就是更新同一 `cert-name`）。备份已在 3.2。

### 3.7 失败时

- `NXDOMAIN` / dig 不到 TXT：DNS 未生效或主机记录写错（不要写成 `_acme-challenge.ssemarket.cn.ssemarket.cn`）
- `Unauthorized`：TXT 值贴错、或多条旧 TXT 干扰 → 删掉旧的 `_acme-challenge` TXT 只留本次
- 超时：重跑 3.4，用新挑战值再改 TXT

验证结束后，可删除 `_acme-challenge` 的 TXT（不影响已签好的证书；下次续期还要再加）。

## 步骤 4：确认新证书内容与路径

```bash
ls -la "$LIVE/"
openssl x509 -in "$LIVE/fullchain.pem" -noout -dates
openssl x509 -in "$LIVE/fullchain.pem" -noout -text | grep -A2 'Subject Alternative Name'
```

**必须看到**：

```text
DNS:ssemarket.cn, DNS:*.ssemarket.cn
```

（顺序可能相反；有无 `www` 等额外名无所谓。）

容器内路径应对得上：

```bash
docker exec "$NGINX" ls -la /etc/letsencrypt/live/ssemarket.cn/
docker exec "$NGINX" openssl x509 -in /etc/letsencrypt/live/ssemarket.cn/fullchain.pem -noout -text \
  | grep -A2 'Subject Alternative Name'
```

## 步骤 5：核对 nginx —— 全部子域共用「这一对」文件

编辑宿主机上的 nginx 配置（现网常见）：

```bash
grep -n 'ssl_certificate' /root/SSE_Market/nginx_proxy/nginx.conf
# 若还有 include 的 conf，一并查：
grep -RIn 'ssl_certificate' /root/SSE_Market/nginx_proxy/ --include='*.conf*' 2>/dev/null
```

每个 `listen 443 ssl` 的 `server`（含 `cloud.ssemarket.cn`、主站、以及将来 `{模块}.ssemarket.cn`）应统一为：

```nginx
ssl_certificate     /etc/letsencrypt/live/ssemarket.cn/fullchain.pem;
ssl_certificate_key /etc/letsencrypt/live/ssemarket.cn/privkey.pem;
```

**不要**为每个子域再写一套 `/live/cloud.ssemarket.cn/` 之类路径（除非你故意维护多本证书）。

若已有 `cloud.ssemarket.cn` 的 server 且已是上述两行 → 证书扩签后 **无需改配置**，直接步骤 6 reload 即可让新 SAN 生效。

以后新增子域 server 模板：

```nginx
server {
  listen 443 ssl;
  http2 on;
  server_name foo.ssemarket.cn;   # 改成实际子域，或 *.ssemarket.cn 需配合默认/catch-all 策略

  ssl_certificate     /etc/letsencrypt/live/ssemarket.cn/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/ssemarket.cn/privkey.pem;

  # ... location / 反代 ...
}
```

## 步骤 6：语法检查并重载

```bash
docker exec "$NGINX" nginx -t
docker exec "$NGINX" nginx -s reload
```

`nginx -t` 必须 `syntax is ok` / `test is successful`。若报找不到证书文件，检查挂载与路径拼写。

## 步骤 7：验收（逐步打勾）

### 7.1 命令行（在任意机器）

```bash
# 主站
echo | openssl s_client -servername ssemarket.cn -connect ssemarket.cn:443 2>/dev/null \
  | openssl x509 -noout -subject -dates

# 已有子域 cloud
echo | openssl s_client -servername cloud.ssemarket.cn -connect cloud.ssemarket.cn:443 2>/dev/null \
  | openssl x509 -noout -text | grep -A2 'Subject Alternative Name'

# 任意未单独申请过的名字（验证通配符）
echo | openssl s_client -servername foo.ssemarket.cn -connect ssemarket.cn:443 2>/dev/null \
  | openssl x509 -noout -text | grep -A2 'Subject Alternative Name'
```

三条都应能看到 `DNS:*.ssemarket.cn`（且握手成功）。

### 7.2 浏览器

1. 打开 `https://ssemarket.cn/` → 锁图标正常  
2. 打开 `https://cloud.ssemarket.cn/` → 正常（若该 server 已配置）  
3. 打开一个 **DNS 已解析、但未必有独立业务** 的地址时：  
   - 证书应显示匹配 `*.ssemarket.cn`  
   - 若 nginx 没有对应 `server_name`，可能落到 default_server（页面不对），但 **证书不应再报「域名与证书不符」**

### 7.3 失败对照

| 现象 | 常见原因 |
|------|----------|
| 证书名不匹配 | 步骤 3 未成功，SAN 仍无 `*`；或 nginx 指向了别的 pem |
| 无法解析 / 超时 | 步骤 2 泛解析未生效 |
| 证书对了但 404/错站 | 缺该 Host 的 `server {}`，与证书无关 |
| reload 后仍旧证 | 浏览器缓存；或看错了另一台机器/CDN |

## 步骤 8：续期（不要只做完签发就走）

通配符 **不能** 再用纯 HTTP webroot 自动续；到期前约 30 天必须再走 DNS-01。

### 方案 A（临时）：到期前人工重跑步骤 3.4–3.5

看现有脚本：

```bash
cat /root/SSE_Market/certbot-renew.sh
crontab -l | grep -i certbot
```

若脚本仍是 `--webroot`，对 `*.ssemarket.cn` **会续期失败**。至少改文档提醒：到期前人工 DNS 验证。

### 方案 B（推荐）：DNS API 插件自动续期

按你们域名所在厂商安装对应 certbot 插件（阿里云 / DNSPod / Cloudflare 等），配置 AccessKey（**不要写进 git**），例如续期命令形态：

```bash
certbot renew \
  --config-dir /root/SSE_Market/Nginx \
  --work-dir /root/SSE_Market/Nginx/work \
  --logs-dir /root/SSE_Market/Nginx/logs \
  --deploy-hook "docker exec sse_market_server-nginx_proxy-1 nginx -s reload"
```

插件需能自动增删 `_acme-challenge` TXT。配好后用：

```bash
certbot renew --dry-run --config-dir /root/SSE_Market/Nginx ...
```

`--dry-run` 成功再依赖 cron。

## 回滚（若新证有问题）

```bash
# 列出备份
ls /root/SSE_Market/Nginx-backup/

# 把步骤 3.2 的备份拷回（把 TIMESTAMP 换成实际）
# 注意：live 下多为 archive 的符号链接，完整回滚建议恢复 live + archive 两份
cp -a /root/SSE_Market/Nginx-backup/live-ssemarket.cn.TIMESTAMP/. "$LIVE/"
# 若有 archive 备份一并恢复后：
docker exec "$NGINX" nginx -s reload
```

回滚后 SAN 会回到旧列表，通配符失效属预期。
