# 流水线 UI + 审计 + sseinfra 建组 CSRF 修复

日期：2026-08-21

## 结论

1. **建组失败根因**：`POST /add` 前未 `GET /add` 刷新 CSRF → 面板返回「表单已过期」。已修 `ensureGroup`，并实测创建/Running/删除探针组成功。
2. **流水线 UI**：模块页步骤条含「获得申请权限」→ 准备包/Agent → 创建组 → Pod → 同步启动 → 完成；「查看日志」弹浮窗（不再整页跳转）。
3. **审计**：表 `audit_logs`；申请提交/审批、建组/删组写入；管理台「审计」Tab；`GET /api/v1/admin/audit-logs`。

## API 契约（实测）

| 动作 | 方法 | Path | Form |
|------|------|------|------|
| 登录 | POST | `/login` | csrf_token, password |
| 建组页 | GET | `/add` | 刷新 csrf |
| 建组 | POST | `/add` | csrf_token, name, cpu, mem, storage |
| 删组 | POST | `/group/{name}/delete` | csrf_token |

## 写操作前强制重登（2026-08-21 修订）

凡 `ensureGroup` / `deleteGroup` / `addDeploy` / `runDeploy` / `stopDeploy` / `setEnv(Many)`：
入口先 `login()`（清空 cookie 后重新登录），再打开目标页取 csrf，再 POST。
批量环境变量用 `setEnvMany` 只登一次。

- 前端：`npm run build:web`；模块页点部署应弹日志浮窗
- 现网：重建 `sdpy-api` 后部署可建组；管理台看审计
