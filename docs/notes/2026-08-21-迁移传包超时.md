# 迁移跳板→GPU 传大数据超时 300s

日期：2026-08-21

## 现象

image 正式迁移约 140MB：`scp` 到跳板成功后，`sudo -u sse scp … gpu:/tmp` 跑满 **300000ms** 被杀。组保留，数据未进 Pod。

## 原因

`sshJump` 默认超时 5 分钟；跳板→GPU 网速慢时不够，且无进度日志。

## 修复

1. 迁移各跳超时至少 **30min**（约 15s/MB）
2. **轮询进度**：三跳均用「前台传输 + 并行轮询」（与 →跳板 相同），每 5s 打进度  
3. 勿用 SSH 管道里的 `nohup/setsid &`：非交互 bash 会挂住，启动阶段无任何进度日志

须 **rebuild + 重启 sdpy-api** 后生效。重试前可清残留：

```bash
pkill -f 'data-.*\.tar\.gz' || true
rm -f /tmp/data-*.tar.gz /tmp/data-*.scp.* /tmp/data-*.kcp.*
sudo -u sse -H ssh gpu 'rm -f /tmp/data-*.tar.gz /tmp/data-*.kcp.*'
```
