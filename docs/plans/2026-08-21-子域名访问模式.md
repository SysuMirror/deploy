# 后续计划：访问模式扩展（子域名）

> 日期：2026-08-21（实现：2026-08-24）  
> 状态：**已落地（多域名）**  
> 背景：路径前缀之外支持平台子域名与自定义域名；一模块多 host、全局查重、保留 cloud/根域。

---

## 1. 现状（已具备）

| 能力 | 说明 |
|------|------|
| 路径前缀 | 平台默认 `root` / `/sdpy`；模块级 `pathMode` |
| 正式/测试 | `/sdpy/{模块}/`、`/sdpy/test/{模块}/`（或根路径等价形式） |
| 网关 | 写 `data/nginx/modules.conf` + `GATEWAY_RELOAD_CMD` |
| sseinfra | 成功后提取 frp 端口作上游，对外仍用路径 URL |

**不支持**：`{模块}.ssemarket.cn` / `{模块}-api.ssemarket.cn` 这类子域名。

---

## 2. 目标

在现有「路径前缀」之外，增加可选 **`accessMode=subdomain`**：

| 环境 | Web | API（可选） |
|------|-----|-------------|
| 正式 | `https://{模块}.{BASE_DOMAIN}` | `https://{模块}-api.{BASE_DOMAIN}` |
| 测试 | `https://{模块}-test.{BASE_DOMAIN}`（或约定 `test-{模块}`） | 对称 |

模块创建/设置可选：`path`（现行）| `subdomain`（本计划）；默认保持 `path`，避免破坏现网。

---

## 3. 依赖与约束

1. **DNS**：`*.ssemarket.cn` 泛解析到公共 nginx / 入口机（运维先到位，否则平台无法生效）。
2. **TLS**：泛域名证书或按模块签发（优先泛域名）。
3. **公共 nginx**：除 `modules.conf` 的 `location` 外，需 `server_name` 块（或按 Host 路由）；与今日「只 include 路径 location」模型不同。
4. **应用侧**：子域名下前端 `base` 一般为 `/`；OAuth `redirect_uri`、图片 `PUBLIC_BASE` 须跟新 URL；sseinfra 仍单端口 8080，仅网关 Host 映射变化。

---

## 4. 建议实现步骤

```text
P0  运维：确认 *.BASE_DOMAIN 解析 + TLS
P1  数据：modules.access_mode / 平台默认 access_mode
P2  routing：buildPublicUrl / modules.conf 按 Host 或独立 conf 生成
P3  部署成功写回：subdomain URL；注入 SDPY_PUBLIC_URL 等
P4  管理台 / 建模块：访问模式选择 + 预览链接
P5  文档：用户部署约定 + OAuth redirect 登记说明
P6  迁移：已有 path 模块可选「升为子域名」并 reload 网关
```

### 网关形态（草案）

- **方案 A**：公共 nginx 增加 `server_name ~^(?<mod>.+)\.ssemarket\.cn$`，`proxy_pass` 到该模块 active 上游端口。  
- **方案 B**：平台继续只写 snippet，由运维维护一张「子域名 → include」模板；平台只更新 upstream 端口映射表。  

优先评估 **A**（改动集中在 SDPY 生成物）；若公共 nginx 策略不允许正则 server，再落 B。

---

## 5. 非目标（本计划不做）

- 自定义任意域名（用户自有域名 CNAME）——可另开计划  
- 按环境多级子域以外的复杂灰度域名  
- 替换现行路径模式（路径前缀长期保留）

---

## 6. 验收（落地时）

- [ ] 新建模块选「子域名」，部署成功后访问链接为 `https://{模块}.{域名}`  
- [ ] 网关 reload 后 HTTP/HTTPS 可达，且与 frp `:23xxx` 上游一致  
- [ ] 路径模式模块不受影响  
- [ ] OAuth / 静态资源在子域名下可用（imagebed 等样例）
